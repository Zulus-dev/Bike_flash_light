# Умный габарит-поворотник-стоп-сигнал для велосипеда  
**Полное техническое описание проекта (редакция 2.6)**

---

## 0. Инструменты разработки

| Инструмент              | Назначение                                      |
|-------------------------|-------------------------------------------------|
| **Blender**             | 3D-моделирование корпуса / визуализация         |
| **KiCad 9**             | Схема и печатная плата                          |
| **VS Code + PlatformIO**| Прошивка (ESP-IDF framework)                    |

Сборка: PlatformIO, board `esp32-c3-devkitm-1`, framework `espidf`, flash 4 МБ, таблица разделов `partitions_ota.csv` (OTA).

---

## 1. Цель проекта

Создать устройство, которое:

- Работает от литиевого аккумулятора 18650 с BMS-платой, выдающей стабильные **+5 В**.
- Управляет каналами: **LED_LEFT**, **LED_CENTER**, **LED_RIGHT**, **LED_STRIP**, **LASER** + зуммер через **ULN2003A**.
- Мониторинг батареи (сглаженный) и **фоторезистор GL5528** в веб-UI.
- Функции: габарит (дыхание), стоп, поворотник, аварийка, охрана, автоаварийка, эффекты вкл/выкл.
- WiFi SoftAP для настройки, мониторинга и **OTA-обновления прошивки**.

## 3. Описание цепей и соединений

### 3.1. Силовая часть

- **BAT+** → вход BMS (BAT+).
- Выход BMS **5V+** → исток (S) Q1 (AO3401A).
- Затвор (G) Q1: R6 к 5V+, R7 к SW1 на GND, сток Q2.
- Сток (D) Q1 = шина **+5V**.
- Q2 (AO3400A): S → GND; G через R9 ← **GPIO21** (POWER_HOLD); R8 подтяжка G к GND.

### 3.2. Питание 3.3 В

Встроенный LDO ESP32-C3 SuperMini. **3V3** → MPU-6050 и делитель LDR (R12 + LDR1).

### 3.3. Светодиоды и зуммер (ULN2003A)

Аноды LED от +5V через 120 Ом; катоды на открытые коллекторы ULN.  
COM ULN → +5V, GND ULN → общая земля.

| Канал ULN | Вход | GPIO      | Нагрузка     |
|-----------|------|-----------|--------------|
| 1         | I1   | GPIO5     | Зуммер       |
| 2         | I2   | GPIO4     | LED_RIGHT    |
| 3         | I3   | GPIO3     | LED_CENTER   |
| 4         | I4   | **GPIO2** | **LED_LEFT** (поворотник) |
| 5         | I5   | GPIO7     | LASER        |
| 6         | I6   | **GPIO20**| **LED_STRIP** |
| 7         | I7   | —         | не используется |

> LED_STRIP на **GPIO20** (не GPIO8). GPIO8 свободен — strapping для USB download.

### 3.4. Мониторинг батареи

```
BAT+ ── R11 100к ──●── GPIO1 (ADC1_CH1)
                   │
                  R10 100к
                   │
                  GND  +  C6 150нФ
```

Делитель 1:2. Замер раз в **3 с**, EMA + среднее за окно **~60 с** (UI без скачков от ШИМ/вибрации).

### 3.5. Фоторезистор GL5528

```
+3.3V ── R12 10к ──●── GPIO0 (ADC1_CH0)
                   │
                LDR1 GL5528
                   │
                  GND  +  C8 100нФ
```

Светло → `ldr_percent` → 0; темно → 100. Общий `ADC_UNIT_1` (`adc1_shared`) для батареи и LDR.

### 3.6. Кнопки и MPU-6050

- SW1 → через R7 на затвор Q1.
- SW2 → GPIO6.
- MPU-6050: SDA = GPIO9, SCL = GPIO10, AD0 = GND, VCC = 3V3.

### 3.7. Сводная таблица GPIO

| GPIO      | Назначение    | Примечание |
|-----------|---------------|------------|
| GPIO0     | LDR (АЦП)     | ADC1_CH0 |
| GPIO1     | Батарея (АЦП)| ADC1_CH1 |
| **GPIO2** | **LED_LEFT**  | Поворотник |
| GPIO3     | LED_CENTER    | |
| GPIO4     | LED_RIGHT     | |

### 3.8. Прошивка по USB

Без снятия ULN (GPIO8 свободен).  
Принудительный download: BOOT (GPIO9) + RESET.

```bash
pio run -t upload
pio device monitor
```

### 3.9. OTA — обновление прошивки по Wi‑Fi

Таблица разделов: **`partitions_ota.csv`**

| Раздел   | Размер (примерно) |
|----------|-------------------|
| ota_0    | ~1,75 МБ          |
| ota_1    | ~1,75 МБ          |

Типичный размер `firmware.bin`: **~0,9–1,2 МБ** — помещается в слот.

**Первый раз** после смены partition table — только USB. Дальше можно только по Wi‑Fi.

#### Где взять файл прошивки

После сборки:

```bash
pio run
```

Файл:

```
.pio/build/esp32c3_supermini/firmware.bin
```

Полный путь (Windows, пример):

```
C:\...\bike_light_esp_idf\.pio\build\esp32c3_supermini\firmware.bin
```

Нужен именно **`.bin`**, не `.elf`.

#### Как прошить по Wi‑Fi

1. Включить устройство, удержать **SW_MODE ≥ 8 с** → SoftAP.
2. Телефон/ПК: сеть **`BikeLight_AP`**, пароль **`12345678`**.
3. Браузер: **http://192.168.4.1**
4. Секция **WiFi** → видна версия прошивки → выбрать `firmware.bin` → **Загрузить прошивку**.
5. Дождаться 100 % и сообщения об OK — устройство **перезагрузится само**.

API: `POST /api/ota`, тело = сырой binary, `Content-Type: application/octet-stream`.

При обрыве загрузки boot остаётся на старом слоте (безопасный откат).

## 4. Принцип работы

- **Габарит** — дыхание LEFT / CENTER / RIGHT; лента и лазер по режимам и LDR.
- **Стоп** — динамическое ускорение (Δg по X/Y относительно медленной базы) + опционально наклон pitch; защита от кочек; подтверждение по времени.
- **Поворотник** — удержание бокового roll ≥ мин. угла; **приоритет над стопом** после старта; max по умолчанию 90°.
- **Аварийка / охрана / автоаварийка** — без изменений по смыслу.

### Стоп (параметры после полевых испытаний)

| Параметр | Поле config | Default | Смысл |
|----------|-------------|---------|--------|
| Порог торможения | `brake_decel_threshold` | 0.45 g | Порог динамического Δg |
| Защита от кочек | `brake_bump_reject` | 5 (1–10) | Жёсткость отсева ударов |
| Подтверждение | `brake_confirm_sec` | 0.08 с | Сколько держать условие |
| Наклон (спуск) | `brake_pitch_deg` | 0 (выкл) | \|pitch\| ≥ порога; 0 = выкл |
| Длительность стопа | `brake_active_time_sec` | 1.5 с | Сколько мигать после события |

Алгоритм: `mag(filtered − slow_base)` по осям X/Y ≥ порога → candidate → confirm → стоп.  
Pitch-стоп **не** срабатывает при сильном боковом наклоне (не мешает поворотнику).

### Поворотник

| Параметр | Default |
|----------|---------|
| Мин. угол | 18° |
| Макс. угол | 90° |
| Удержание | 0.8 с |
| Время сигнала | 8 с |

Инверсия сторон — один раз (флаг `invert_turn_signals`), без двойного переворота в state machine.

### Режимы ленты / лазера

Без изменений: `strip_mode` (off / always / dark_only / scale), `laser_mode` (off / always / dark_only / brake_only_dark).

## 5. Кнопка SW_MODE

| Удержание | Действие |
|-----------|----------|
| < 1 с     | Обычный ↔ Аварийный |
| 2–4 с     | Выключение питания |
| 4–8 с     | Постановка / снятие охраны |
| ≥ 8 с     | WiFi SoftAP вкл/выкл |

## 2. Секции настроек

### Управление (`ctrl`)

| Кнопка | Действие |
|--------|----------|
| На охрану / Снять | MODE_ALARM |
| Калибровка | MPU offsets → NVS |
| Ребут | `esp_restart` |
| Выключить | POWER_HOLD off |

### Габарит (`breath`)

Период дыхания, яркость крайних, яркость центра.

### Стоп (`brake`) — актуально после полевых испытаний

| Параметр | ID UI | Описание |
|----------|-------|----------|
| Порог торможения | `brake` | Динамическое Δg (не сырой ax). Рекомендуется 0.35–0.50 |
| Период мигания | `bper` | |
| Длительность стопа | `bact` | Сколько мигать после события |
| Яркость стопа | `bbr` | |
| **Защита от кочек** | `bbump` | 1–10 (выше = жёстче отсев ударов) |
| **Подтверждение тормоза** | `bconf` | 0.04–0.40 с удержания условия |
| **Наклон вперёд (спуск)** | `bpitch` | 0–45°; **0 = выкл**. Срабатывает по \|pitch\| |

Стоп по pitch **не** активен при сильном боковом наклоне (чтобы не мешать поворотнику).

### Поворот (`turn`)

| Параметр | Рекомендация |
|----------|--------------|
| Мин. угол | 15–20° |
| Макс. угол | **90°** (не ставить 60 — сильный наклон иначе «выключает» поворот) |
| Удержание | **0.5–1.0 с** |
| Время сигнала | 8 с |
| Инверсия сторон | если лево/право перепутаны |

После удержания наклона **поворотник имеет приоритет** над стопом.

### Авто / Охрана / LDR / Лазер / Лента / Эффекты / Звук

Без смены смысла относительно 2.6 (автоаварийка, пороги охраны, LDR, режимы laser/strip, мелодии).

### WiFi (`wifi`) + **OTA**

| Элемент | Описание |
|---------|----------|
| SSID / Пароль / Канал / Таймаут | Параметры SoftAP |
| **Версия прошивки** | Из `esp_app_get_description()` |
| **Файл .bin** | Выбор файла на телефоне/ПК |
| **Загрузить прошивку** | `POST /api/ota`, прогресс-бар |

## 3. Инструкция: прошивка по Wi‑Fi (OTA)

### 3.1. Получить файл прошивки на компьютере

В каталоге проекта PlatformIO:

```bash
pio run
```

Готовый файл:

```
bike_light_esp_idf/.pio/build/esp32c3_supermini/firmware.bin
```

Примеры полного пути:

- **Windows:** `C:\Users\<имя>\...\bike_light_esp_idf\.pio\build\esp32c3_supermini\firmware.bin`
- **Linux/macOS:** `.../bike_light_esp_idf/.pio/build/esp32c3_supermini/firmware.bin`

Только **`firmware.bin`**. Файлы `.elf` / `.map` для OTA не подходят.

Размер обычно **~0,9–1,2 МБ**; слот OTA ~1,75 МБ — запас есть.

Скопируйте `.bin` на телефон (облако, USB, мессенджер) или откройте UI с того же ПК, где лежит файл.

### 3.2. Первый раз после смены таблицы разделов

Если на плате ещё **не** была прошивка с `partitions_ota.csv`:

```bash
pio run -t upload
```

Только по **USB**. Дальше можно обновлять по Wi‑Fi.

### 3.3. Загрузка по Wi‑Fi

1. Питание устройства включено.  
2. Удержать **кнопку режимов ≥ 8 секунд** → SoftAP.  
3. Подключиться к Wi‑Fi **`BikeLight_AP`**, пароль **`12345678`**.  
4. Браузер: **http://192.168.4.1**  
5. Открыть секцию **WiFi**.  
6. Убедиться, что видна текущая **версия**.  
7. **Выбрать файл** → указать `firmware.bin`.  
8. Нажать **«Загрузить прошивку»**.  
9. Дождаться прогресса 100 % и «OK — перезагрузка…».  
10. Устройство перезапустится само; через ~10–20 с снова можно подключиться к AP (если SoftAP включите повторно).

Не выключайте питание и не отходите от AP во время загрузки.

### 3.4. Если OTA не прошла

- Проверьте, что файл именно `.bin` и размер > 50 КБ.  
- Перезапустите SoftAP (≥ 8 с).  
- При необходимости прошейте по USB: `pio run -t upload`.  
- При обрыве обычно остаётся **старая** рабочая прошивка (второй слот не активируется).

## 4. Связь с железом

- LDR GPIO0, батарея GPIO1, LED_LEFT GPIO2, LED_STRIP GPIO20, LASER GPIO7, POWER_HOLD GPIO21.  
- SoftAP только пока включён кнопкой (≥ 8 с) или из охраны.  
- Настройки → NVS; смена размера `bike_config_t` сбрасывает на defaults — после крупного обновления заново **Сохранить** нужные слайдеры.
